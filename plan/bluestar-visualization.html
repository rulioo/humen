蓝星可视化方案

结论先行：用 Unity 3D，不用 Cesium。 Cesium 是给真实地球的地理数据做的可视化引擎 —— 而本项目的地形、 影像、大陆全部是程序化生成的，恰好没有一样用到它的核心价值。

结论

Unity 3D（本机已装的 Unity 6 · 6000.0.30f1）

三条理由，任一条都足以定案：① Cesium 的全部价值在于流式加载真实地形与影像， 我们没有真实数据；② 本项目的模拟内核是纯 C#，Unity 也是 C# —— 两边可以直接共享代码， 而 Cesium 的两条路（CesiumJS 是 JavaScript、Cesium for Unity 依赖 Cesium ion 在线资产） 都要在中间加一层翻译，而这一层会**威胁 INV-34 的逐位可复现**； ③ `req.txt` 第 1 行写的就是 Unity3D。

Cesium 为什么不合适

这不是说 Cesium 不好 —— 它在自己那一行里是最好的工具之一。 问题是把它逐项对照本项目的需求，会发现它提供的每一项我们都不需要， 而我们需要的每一项它都不提供。

Cesium 的核心能力 它解决什么问题 本项目需要吗
3D Tiles 流式加载 城市级模型按视锥分块加载，几百 GB 数据也能流畅浏览 不需要
整颗星球才 32 514 个顶点 · 3.6 MB，一次全装进显存
quantized-mesh 地形瓦片 真实高程数据（SRTM / 激光雷达）的多分辨率金字塔 不需要
高程由 §7.4 的噪声函数现算，没有任何外部数据
WGS84 椭球与地理精度 让坐标与真实 GPS 对齐，做测绘级应用 不需要
蓝星是虚构星球，只要 R=1000 的球面几何自洽即可
影像图层（Bing / 天地图…） 给地球贴真实卫星照片 不需要
陆地颜色由 §7.7 的群系决定
Cesium ion 在线资产 托管的地形 / 影像 / 模型服务 不需要
引入账号与网络依赖，且与 §8.5「CI 可复现」冲突
时间动态实体（CZML） 实体带时间区间，随时刻出现 / 消失 / 移动 需要 · 但可自建
这是唯一值得借鉴的，见下方「借用其思想」
两条路的共同障碍：C# 内核被隔在了外面。 CesiumJS 是 JavaScript —— 要用它就得把 30 万年的模拟要么用 JS 重写、 要么编译成 WASM 再跨语言调用。而 INV-34 要求Hashing.Hash64 与 Rng 的逐位一致，跨语言重实现是这类项目最经典的自毁方式：某天哈希差一位， 「同种子两次构建逐位相同」就悄悄不成立了，而外观上看不出任何异常。
值得从 Cesium 借走的一件事：时间动态实体的组织方式。 它把「实体 + 可用时段」作为第一性对象的做法，正是我们要的时间轴模型 —— 拖到公元前 5 万年，该出现的聚落出现、该消失的消失。 借它的思想，不引它的依赖。

尺度：整个方案的第一个约束

在谈"怎么渲染"之前必须先看一组数。蓝星的 R = 1000 units = 6371 km， 于是 1 unit = 6.371 km：

行星 蓝星本体 · 5 块大陆 · 10.89 % 陆地 R = 1000 unit
大陆 一座城 · 直径约 5 km 0.78 unit
部落 一个村落 · 直径约 500 m 0.079 unit
建筑 一间房子 · 高 6 m —— 玩家最想看清的东西 0.00094 unit

一间房是星球半径的百万分之一。所以"拉近看建筑"在几何上是不可能的 —— 拉近 5 个数量级已经不是缩放，是另一个场景了。这就是三级视图的由来。

顺带解决了一个不那么明显的问题：浮点精度。 假设不做分级，把聚落直接建在球面上 —— 世界坐标的量级是 1000， 而 float32 在这个量级上的最小可分辨间隔约 6.1e-5。 一间 6 m 的房子只有 9.4e-4 单位，横竖只跨十几个浮点台阶， 建筑会肉眼可见地抖动、Z-fighting。 「聚落单独一个场景、坐标居中在原点」最初只是为了让玩家看得清 —— 现在它是数值上的必需品。

四个关键技术决定

决定 01

三级视图

轨道（发光点）→ 大陆（聚落斑块）→ 聚落（真实建筑）。 只有焦点部落拥有完整几何。

与 §3.1 对齐模拟层的「焦点部落」与渲染层的「焦点部落」是同一个焦点 —— 玩家"点进去"在两层的含义一致，不会穿帮成"看得见一千个村民却不模拟他们"。

决定 02

B→C 是「降落」，不是缩放

点选部落 → 切入一个独立的局部场景，坐标居中在原点。

两个理由B 到 C 差 6371 倍，连续缩放要让 100 个部落都持有完整几何；且居中在原点同时消除了浮点抖动。局部地面可以铺平地 —— 5 km 跨度上球面只下垂 0.49 m。

决定 03

时间轴是纯函数，不是累加器

拖拽滑条 = SeekTo(年)，不是"快进"。 时钟按整数年推进，绝不用 Time.deltaTime 驱动模拟。

为什么INV-12 / ID-15 要求结果与帧率、播放速度、LOD 无关。一旦让 deltaTime 参与，同一年的世界在 30 fps 和 60 fps 下就会分叉。

决定 04

Core 多目标编译

Core 从 net8.0 扩为 net8.0;netstandard2.1， 让 Unity 6 与 CLI 共用同一份源码。

已知的坑PlanetRaster 用了 System.Numerics.BitOperations.PopCount，那是 .NET Core 3.0+ 的 API，netstandard2.1 里没有 —— 需要一个小 shim 或条件编译。这是唯一的移植点。
